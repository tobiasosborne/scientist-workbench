1. P2 — meijerg-contour-cost-bound (Layer 5 follow-up)
----------------------------------------------------------------------

Title: `meijergContour`: cost-bound truncation cap for one-sided pole
       clusters at |z| ≥ 1.

Background:
The contour layer's `pickTruncation` doubles T up to 20 times when the
integrand tail does not fall below `peak · 2^-X`. For `m = 0 ∨ n = 0`
inputs (one-sided Γ-pole cluster) at `|z| ≥ 1`, the tail decays slower
than the Stirling estimate predicts, and `pickTruncation` exits the
loop with T ≈ 4×10^7. The subsequent quadrature driver iterates for
thousands of evaluations without convergence, eventually returning
`{ converged: false }` — but the user's CLI invocation has already
been waiting tens of seconds.

The dispatcher's `canUseContour` predicate (ADR-0027 §2) shadows this
behaviour with an upfront refusal. Cost-ascending dispatch routes
around the contour layer cleanly to Slater or asymptotic. So the user-
facing impact via `tools/meijer-g` is zero. But:
- `tools/meijer-g --force-method=contour` would hit the hang if the
  dispatcher didn't honour its own predicate (it does; ADR-0027 §2
  documents the special-case).
- Direct callers of `meijergContour(...)` from `@workbench/meijer-core`
  bypass the dispatcher predicate.

Fix:
Add a hard cost cap inside `pickTruncation` itself. After the 20
doublings, compare the tail magnitude to the threshold; if still too
large, surface a structured refusal `{ status: "cost-bound-truncation",
reason: "..." }` instead of returning the inflated T to the
quadrature driver. This bumps `meijergContour`'s refusal class
roster; documented in a follow-up ADR or a bullet in ADR-0022.

Acceptance:
- New refusal class `cost-bound-truncation` returned on the
  one-sided-cluster regime within ~10 ms.
- `meijergContour` direct callers see the structured refusal.
- `canUseContour` predicate stays as-is (defence-in-depth).
- 3+ test cases exercise the new refusal path
  (`packages/meijer-core/test/contour.test.ts`).

Priority: P2 (the dispatcher already routes around; this is for
direct callers and substrate hygiene).

Depends on: nothing (substrate hygiene).

2. P3 — meijerg-method-disagreement-audit
----------------------------------------------------------------------

Title: Audit method-agreement on the full `bench/meijer-g/` battery.

Background:
The `tools/meijer-g` wire test exercises 8 method-agreement cases
over Slater + asymptotic. The full `bench/meijer-g/` battery
(`hv0.11`) will run ~150 cases through cost-ascending dispatch.
Some cases will run through different lanes than the test suite
covers; some may exhibit method-disagreement that the fast test
didn't catch. Audit the bench output looking for:

- Numerical disagreement between dispatch lanes ≥ 1e-(precision − 5).
- Lanes that should agree (same result.method, same regime) but
  produce drift > the asymptotic error estimate.
- Edge cases at the |z| boundary where Slater's quarantine band
  and contour's decay condition are both nominally satisfied.

Fix:
Run each `bench/meijer-g/` case through every applicable
`--force-method=<lane>` and record. Flag cases where lanes
disagree past a threshold; for each flagged case, file a
sub-bead with the specific input, the per-lane outputs, and a
suspected algorithmic cause (working-precision insufficient,
prefactor sign error, branch-cut convention drift between layers).

Acceptance:
- An audit log under `bench/meijer-g/method-agreement-audit.json`.
- Zero cases with disagreement > 1e-(precision − 8).
- For any case that does disagree, a follow-up sub-bead is filed.

Priority: P3 (depends on `hv0.11` golden battery shipping first).

Depends on: hv0.11.

3. P3 — meijerg-quarantine-fallthrough
----------------------------------------------------------------------

Title: Genuine fallthrough cases — file targeted asymptotic-extension
       beads for the non-coverable regime.

Background:
Some inputs fall through *every* lane:
- `|z| ≈ 1, p = q, m + n ≠ p`: Slater quarantine + Stokes regime,
  contour decay borderline, asymptotic outside |z|>1.
- `arg z ∈ [π/2 - π/64, π]`: secondary sector for the asymptotic;
  contour decays but cost-unbounded for some shapes; Slater applies
  but slow convergence.

The dispatcher refuses these honestly via `tagged
"meijer-g/out-of-region"`. But the verifier (`hv0.11`) has cases
in this regime; the refusal is correct *for v0.1* but the user
ultimately wants a value.

Fix:
For each genuinely-uncoverable regime, file a sub-bead specifying:
- The mathematical regime.
- The proper algorithmic extension (full Braaksma sectorial
  connection coefficients for arg z ∈ [π/2, π]; saddle-point contour
  deformation for the quarantine band; analytic continuation across
  the cut).
- The sub-bead expected scope (one ADR + one kernel + tests).

Anticipated children:
- hv0.9.5 (secondary-sector handling, already named in worklog 078).
- hv0.5.1 (analytic continuation for `|z| ≈ 1` quarantine; saddle-
  point contour deformation per Paris-Kaminski ch.2).

Acceptance:
- Each genuine fallthrough class has a filed bead with the regime,
  the algorithmic extension, and the expected scope.
- The list is part of the `hv0.11` battery's "expected refusals"
  pinning, so a future "we shipped X — re-run the bench" check is
  immediate.

Priority: P3 (post-`hv0.11`).

Depends on: hv0.11.

4. P2 — lc1-arbprec-precision-flag-wiring (pre-existing, inherited)
----------------------------------------------------------------------

Title: Runner doesn't thread `--precision=N` standard flag into
       arbprec tool `fn`'s `flags` object.

Background:
ADR-0020's `--precision=N` standard flag is parsed by the runner
(`packages/contract/src/runner.ts`) and made available in
`stdFlags["precision"]`, but the code that builds the per-tool
`toolFlagsTyped` object only iterates `Object.keys(toolFlags)` —
which does *not* include `precision` because arbprec tools don't
declare it in their own `flags` (it's the standard flag they
inherit via `mergedFlags`).

The result: every arbprec tool's `fn(input, flags)` sees
`flags.precision === undefined` on CLI invocation. Tools work
around this by reading `(flags as { precision?: bigint }).precision
?? 50n` — every CLI invocation runs at default `precision = 50`.

In-process callers via `@workbench/compose` (`runWorkbench`) thread
flags directly to `executeToolDef`, so the bug is CLI-only.

Fix:
In `packages/contract/src/runner.ts`, when `def.arbprec === true`,
include `precision` in the `toolFlagsTyped` object even though it's
not in `def.flags`. The simplest patch is:

```ts
const toolFlagsTyped: Record<string, unknown> = {};
for (const k of Object.keys(toolFlags)) {
  toolFlagsTyped[k] = (parsed.flags as Record<string, unknown>)[k];
}
if (def.arbprec === true) {
  toolFlagsTyped["precision"] = (parsed.flags as Record<string, unknown>)["precision"];
}
```

Affected tools (every `arbprec: true` wire tool):
- `tools/hypergeometric-pfq`
- `tools/meijer-g-slater-only`
- `tools/meijer-g-asymptotic-only`
- `tools/meijer-g` (this session)
- (any future arbprec tools)

Plus `bench/hypergeometric-pfq` (worklog 078) which works around
this via `executeToolDef` directly.

Acceptance:
- After fix, `bun tools/meijer-g/tool.ts --precision=80 < input.json`
  honours the `--precision=80`.
- All four arbprec tools' tests pass byte-identically (their
  in-process `def.fn` calls don't change behaviour).
- A new test in `packages/contract/test/runner.test.ts` exercises
  the CLI surface with `--precision=N` and verifies the flag
  reaches `fn`.

Priority: P2 (workaround exists; lifts the workaround for every
arbprec tool's CLI surface).

Depends on: nothing.

5. P3 — meijerg-tier-h-speed-gate (forward-looking)
----------------------------------------------------------------------

Title: Tier-H speed-gate optimization paths for `tools/meijer-g`.

Background:
Per `tstournament/.../problem-13/DESCRIPTION.md` Tier H, the
verifier requires 50 dps in ≤ 1.5 s/case across 200 cases.
Current dispatcher cost (informal):
- Symbolic match: ~ 1 ms.
- Slater Series 1/2: 1–100 ms.
- Contour: 50 ms – 5 s.
- Asymptotic: 1–100 ms.

The contour lane's 5 s ceiling is the load-bearing concern for Tier
H. Optimization paths:
- Faster Γ products (Stirling-budget tuning in `cgamma`).
- Caching `clog(z)` between integrand calls (already done).
- Adaptive contour offset for asymmetric `arg(z)` (currently
  symmetric truncation `[-T, T]` is conservative).
- Saddle-point deformation (Paris-Kaminski ch.2).

Acceptance:
- Tier H cases all complete in < 1.5 s/case at 50 dps.
- Dispatcher's cost-ascending discipline holds: no regressions
  on the current method-agreement self-tests.

Priority: P3 (depends on `hv0.11` battery to know which cases are
slow).

Depends on: hv0.11.
