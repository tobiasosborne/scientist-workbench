TITLE: hv0.9.1 — Full H_{p,q} algebraic series for `n < p` regime
TYPE: feature
PRIORITY: 2
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9
DESCRIPTION:
v0.1 of the Braaksma asymptotic (`packages/meijer-core/src/asymptotic.ts`)
ships only the n-pole (right-pole) algebraic series — equivalent to
Slater Series 2 read asymptotically. The full Braaksma theorem
admits a more general algebraic form `H^{m,n}_{p,q}(z)` (DLMF
16.11.2; Paris-Kaminski 2001 §2.2) that decouples from Slater's
prefactor when `n < p` (the upper "extra" parameters in `ap` are
not residue centres). Implementing it lets the asymptotic cover
parameter shapes that the Series-2 pre-factor mishandles and is
the prerequisite for the E-series exponential terms (hv0.9.1
follow-up).

Acceptance:
- Implement `H_{p,q}(z)` per DLMF 16.11.2.
- Test cases where `n < p` and Slater Series 2 prefactor differs
  from the H-series prefactor; cross-validate against mpmath at
  60 dps.

TITLE: hv0.9.2 — Stokes-line connection coefficients
TYPE: feature
PRIORITY: 2
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9, hv0.9.1
DESCRIPTION:
The v0.1 asymptotic refuses inputs within `2^{-workingBits/4}` of
`|arg z| = π/2 - π/64` (the Stokes-line band). Crossing the line
activates exponentially-small contributions from the `E_{p,q}(z)`
exponential series (DLMF §16.11; Paris-Kaminski 2001 §2.3 Stokes-
multiplier table). Implement the table for the `(m, n, p, q)`
shapes that the bench battery probes; widen the principal-sector
cap accordingly.

References:
- Paris & Kaminski 2001 *Asymptotics and Mellin-Barnes Integrals*
  CUP, §2.3.
- DLMF §16.11(iii) the regime-by-regime combinations table.

Acceptance:
- Stokes-multiplier table covers at least `p = q` and `p ≤ q − 2`
  regimes.
- Cross-validation against mpmath / Wolfram on inputs sweeping
  across `arg z = ±π/2`.

TITLE: hv0.9.3 — Olde Daalhuis–Olver hyperasymptotic refinement
TYPE: feature
PRIORITY: 3
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9, hv0.9.2
DESCRIPTION:
The v0.1 asymptotic is "superasymptotic" (Olver 1974 §3.7):
truncated at `k*` it has error `|t_{k*+1}|`. Hyperasymptotics
(Olde Daalhuis & Olver 1995, *Methods Appl. Anal.* 2: 173–197)
recovers exponentially-small accuracy across Stokes lines via
Borel resummation of the divergent tail. Multi-session-scale work;
beyond v0.1 budget.

References:
- Olde Daalhuis & Olver 1995 *Methods Appl. Anal.* 2: 173–197.
- Berry & Howls 1990 *Proc. R. Soc. Lond. A* 430: 653-668.

Acceptance:
- Implement at least the level-1 hyperasymptotic refinement (the
  first re-expansion of the tail).
- Verify accuracy improvement: at fixed precision, the
  hyperasymptotic answer is one Stokes-multiplier order more
  accurate than the v0.1 superasymptotic.

TITLE: hv0.9.4 — Symmetric `|z| → 0` asymptotic
TYPE: feature
PRIORITY: 2
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9
DESCRIPTION:
v0.1 ships the n-pole (right-pole, `|z| → ∞`) asymptotic. The
mirror m-pole (left-pole, `|z| → 0`) asymptotic uses the lower-
pole residues `s = -b_h - k` and the same optimal-truncation
machinery applied to a series in `z` instead of `1/z`.
Implementing it covers shapes with `n = 0` (which the v0.1
refuses with `no-pole-residues`) and gives the dispatcher a
clean fast-path for `|z| → 0` inputs.

Acceptance:
- New entry point `meijergAsymptoticSmallZ(params, z, prec, opts)`
  or unified `meijergAsymptotic(...)` with a sector-tag that
  picks the right side.
- Cross-validation against the Series 1 convergent path on
  overlap region.

TITLE: hv0.9.5 — Secondary-sector handling (`|arg z| > π/2 − π/64`)
TYPE: feature
PRIORITY: 3
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9, hv0.9.1, hv0.9.2
DESCRIPTION:
v0.1 refuses inputs in the secondary sector with `tagged
"meijer-g-asymptotic-only/secondary-sector"`. The full
Braaksma 1964 theorem provides connection coefficients between
sectors that — combined with the H-series (hv0.9.1) and Stokes-
multiplier table (hv0.9.2) — let us compute the asymptotic in any
sector. Last piece of the full Braaksma theorem.

Acceptance:
- Sector classifier widens to admit `|arg z| ∈ [π/2 - π/64, π]`
  for parameter regimes the connection-coefficient table covers.
- Cross-validation on the negative-real-axis (`arg z = π`) cases.

TITLE: arbprec runner — `--precision` flag wiring fix
TYPE: bug
PRIORITY: 2
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.9
DESCRIPTION:
The runner (`packages/contract/src/runner.ts`) parses `--precision=N`
correctly for arbprec tools (it's added to `mergedFlags` for argv
parsing) but does NOT inject the parsed value into `toolFlagsTyped`
(the object passed to `def.fn`). The relevant code at runner.ts
lines 497-500:

```
const toolFlagsTyped: Record<string, unknown> = {};
for (const k of Object.keys(toolFlags)) {       // toolFlags = def.flags only
  toolFlagsTyped[k] = (parsed.flags as Record<string, unknown>)[k];
}
```

`Object.keys(toolFlags)` iterates only over *tool-declared* flags
(`def.flags`); `precision` is added by `mergedFlags` for arbprec
tools but lives in `parsed.flags` not in `toolFlags`. So every
arbprec-tool's CLI invocation runs at the default precision = 50
dps regardless of the `--precision` flag.

Affected tools (currently): `hypergeometric-pfq`,
`meijer-g-slater-only`, `meijer-g-asymptotic-only` — all share the
same `(flags as { precision?: bigint }).precision ?? 50n` access
pattern. In-process callers passing `flags` directly to `def.fn`
work; CLI invocations don't.

Fix: in runner.ts, after the existing loop, conditionally add
`precision` to `toolFlagsTyped` for `def.arbprec === true`. One-
line change; will need tests on each affected tool's CLI.

Acceptance:
- `bun tools/<arbprec-tool>/tool.ts --precision=30` produces
  output with `achieved_precision = 30`.
- All arbprec tools' goldens regenerated to honour the per-case
  `flags.precision` setting.
- Test added to a contract-level test file ensuring future arbprec
  tools' CLI honours the flag.
