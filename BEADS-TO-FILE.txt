TITLE: meijer-core dispatch: argument-transformation infrastructure
TYPE: feature
PRIORITY: 3
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.6
DESCRIPTION:
Bateman §5.6 (12)–(15) and several DLMF §16.18 reductions involve
an *argument transformation* on the input `z` — typical example:
the trigonometric reductions like `G^{1,0}_{0,2}(_; 0, 1/2 | z²/4)`
where the input z is `z²/4`, and the closed form is `cos(z)`. v0.1
of the dispatcher does not handle these (ADR-0025 §10 lists this as
out-of-scope). Add an optional `argTransform: { kind: "scale-square",
factor: Value }` field to `ReductionRule` and a corresponding
inverse-transformation step in `dispatch.ts`. Test by re-enabling
the deferred trigonometric reductions in `bateman-5-6.ts` (which v0.1
left as comment-anchors).

TITLE: meijer-core dispatch: richer pattern grammar (linear relations, recursive G)
TYPE: feature
PRIORITY: 3
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.6
DESCRIPTION:
v0.1 ships `SlotSpec ∈ {lit-int, lit-rat, free, free-shift}` and
`RelationSpec ∈ {integer-difference}`. As the rule corpus grows past
~200 rules, several PBM and Wolfram entries need richer pattern
shapes:
* `linear-relation`: cross-slot guard `c1·a + c2·b = c3` for
  arbitrary integer coefficients.
* `pattern-list`: matching a sub-tuple's *length* dynamically (some
  PBM entries are families parametrised by the count of integer
  spacings, e.g. `Γ(1+a) Γ(1+a−1) … Γ(1+a−k)` for arbitrary k).
* `recursive-G`: rule's RHS is a smaller Meijer G; v0.1 emits the
  bare reduced head, but downstream `tools/meijer-g` (top-level
  dispatcher, hv0.10) needs to recurse into it. Add a stop-condition
  to prevent infinite recursion + a depth limit.
Add tests for each new grammar feature using a curated rule from
PBM that needs it.

TITLE: meijer-core dispatch: per-head arbprec evaluator (Gamma, BesselJ, BesselK, ...)
TYPE: feature
PRIORITY: 2
PARENT: scientist-workbench-hv0
DEPENDS-ON: scientist-workbench-hv0.6
DESCRIPTION:
The dispatcher emits AST in the special-function vocabulary
(ADR-0023). To consume those ASTs *numerically* at arbitrary
precision (for problem-13 Tier A / B verifier cross-validation, and
for the eventual `tools/meijer-g` numerical fall-through), we need
per-head arbprec evaluators: `Gamma(z, prec) → BigComplex`,
`BesselJ(ν, z, prec) → BigComplex`, etc. The substrate is mostly
there: `@workbench/bigfloat::cgamma` already exists; `BesselJ` etc.
need new code (e.g. via the AST's reduction back to `pFq` from
`@workbench/hypergeometric` plus a Γ-prefactor). Lands in a new
`packages/special-eval` package or as additive extensions of the
existing per-head packages. Cross-validated against
`mpmath.gamma / mpmath.besselj / etc.` byte-for-byte.
